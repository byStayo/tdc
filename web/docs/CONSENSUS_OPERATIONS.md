# Visual consensus publication and evaluation

This extends the prior editorial publication. The full user goal remains open. A responsive interface and unconnected feed cards are not completion of the requested product.

## Commands

- `npm run consensus:collect`: bounded official-source collection into private `.consensus/last-collection.json`; no public change.
- `npm run consensus:publish`: validate, attach any qualified active model, archive a new immutable snapshot, and atomically replace the current edition. Re-fetching identical observations does not create an edition. Shares `.editorial/publish.lock` with editorial publishing and evaluation.
- `npm run consensus:review`: attach the saved, source-checked editorial review to the existing data without refetching providers. Publish only if the facts or interpretations changed. Source observation/retrieval dates remain intact; this is not a new market-data collection.
- `npm run consensus:private-credit`: collect only the Fed private-credit source into a private candidate while retaining all other saved observations. Add `-- --publish` for a reviewed immutable publication. The current and dated tables must agree; a new release needs an explicit review of its PDF units and underlying-data cutoff in `private-credit.ts`. Refetching unchanged data creates no edition. The normal full collector includes this source too.
- `npm run consensus:evaluate`: preserve existing outcomes; calculate per-target performance and candidate eligibility. With no price evidence it records an explicit pending state.
- `npm run consensus:evaluate -- --prices /absolute/private/approved-prices.json`: score new resolved outcomes using a reviewed price feed and complete exchange-calendar evidence. File is an array of `PriceEvidence` contracts from `lib/consensus/evaluation.ts`. Source must be a public HTTPS citation without credentials; ETF evaluation requires total-return-adjusted prices, including both splits and distributions. Unadjusted and split-only inputs are rejected. Keep the raw evidence private and record the provider's actual display and training permissions before use.
- `npm run consensus:research-fx`: optional fixed research experiment from the official ECB historical XML saved privately as `.consensus/ecb-history.xml`. Uses approximately 3,000 recent reference fixes. This is latest-vintage reconstruction, never an as-issued equity track record. Do not tune against the held-out test after seeing its results.
- `npm run consensus:finra-setup`: owner-run Terminal command with hidden prompts, saving a private local credential outside the repository. No network request. See `FINRA_SETUP.md` for the exact FINRA steps.
- `npm run consensus:finra-private`: authenticated private verification after secure free-Public credential setup. Uses the private local file or both explicit environment variables. No public publication. See `FINRA_SETUP.md` for the distribution boundary.
- `npm test`, `npm run typecheck`, `npm run build`: build automatically verifies current/archived snapshot hashes, chronology and active model artifacts.

The morning view displays up to three scoped developments. News reviews carry no directional score, avoiding an extra vote for the same earnings or rates fact. Prospective models are separate for each supported instrument and horizon. Scoring and training use `last-edition-before-entry-open-v1`: exactly one edition per instrument/horizon/entry session, chosen by publication time regardless of its result or abstention. Earlier rows remain unchanged in `outcomes.json`; `outcome-selection.json` identifies superseded editions. MARKET itself is unscored. Its interface summarizes instrument cohorts only for the selected horizon.

The `prospective-walk-forward-2` gate requires at least500 resolved observations,50 training rows with both labels,20 validation rows and100 new non-overlapping test windows. Initial60/20/20 chronological boundaries purge labels crossing split boundaries. Later test windows must begin after the last consumed label resolves, even when no incumbent was promoted. Greedy chronological selection excludes overlapping weekly/monthly label windows. At least20 newly resolved labels are required on every attempt. Longer horizons therefore need substantially more than500 raw observations. Normalization uses training only; four regularization choices compete on validation only. Historical FX experiments remain separate and cannot activate these models.

Before fitting/evaluating, the locked evaluator appends and fsyncs an immutable `public/consensus/evaluations/<instrument>-<horizon>-<attempt>.json` reservation. It records test IDs/windows, dataset hash and `consumedThrough`, with no raw prices. Failure or interruption still consumes that window; never delete or reset it. Missing reservation history for an already evaluated candidate fails closed. A legacy untracked evaluated artifact requires explicit audit migration; none existed when this policy was introduced. Do not rerun or relabel the nine saved historical FX experiments to satisfy this gate.

Promotion must improve Brier by more than0.01 against the training base rate,50/50 and any incumbent, with a positive basic-bootstrap95% lower bound and a one-sided paired-loss test below the declared alpha. Circular blocks use length`ceil(cuberoot(n))`,at least19,999resamples and a fixed dataset-derived seed. Bonferroni across15cohorts plus attempt budget`0.05/(15*n*(n+1))` is deliberately more conservative than a batch Holm gate and also limits repeated attempts. Bootstrap evidence is approximate under serial dependence; non-overlap does not establish independence. Resampling resolution grows to max(19,999, ceil(4/alpha)-1) with a cap of1,999,999 resamples; exceeding the cap stops before a test is inspected. Attempt8 can therefore qualify rather than being impossible by construction. Do not retry the same holdout with tuned settings. A methodology revision needs a fresh future test window.

Method references: [scikit-learn chronological evaluation and test-set leakage](https://scikit-learn.org/stable/modules/cross_validation.html), [SciPy paired/basic bootstrap definitions](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html), and [arch circular block bootstrap](https://arch.readthedocs.io/en/latest/bootstrap/generated/arch.bootstrap.CircularBlockBootstrap.html). These describe the methods, not the product's predictive performance. The thresholds and alpha schedule above are declared product policies.

The evaluator archives candidate and active-model artifacts and updates the registry only when gates pass. Prebuild and publication validate active promotion evidence against its durable reservation. Reports distinguish the current candidate's promotion from an already active incumbent. Future snapshots freeze model ID, training time and probability. Historical outcomes retain their original model and price basis. To roll back, select a previously archived compatible active model, record the reason and change the registry under the shared publication lock; do not rewrite old snapshots, outcomes or consumed-test reservations.

## Evaluation recovery, rollback and pending coverage

Evaluation prepares one fsynced private journal for its candidate/active artifacts, outcome ledger, selection record, registry and performance report. The shared lock covers reading the input editions and replaying the transaction. On restart, the evaluator finishes the recorded writes and exits without fitting a model or inspecting another test window. `npm run consensus:recover` performs the same bounded replay explicitly. Prebuild and consensus publication refuse a pending transaction. Recovery verifies every before/after content hash and destination before changing any file; intervening edits, symlinks, unsafe destinations and replacement of immutable model artifacts fail closed. Completed journals remain private. This gives recovery and deployment consistency; separate files are not an atomic filesystem group for an arbitrary local reader. Evaluation reservations and their consumed windows remain durable regardless of transaction outcome.

The tracked `lib/consensus/evaluation-state.json` contains only transaction status and content hashes of the four mutable evaluation ledgers plus a cumulative inventory of immutable model/candidate and rollback-action files. Both the pending marker and private journal retain the inventory across interrupted replay; later transactions keep earlier artifact hashes. It is durably marked pending before any output changes and complete only after all outputs are durable. Unlike the private journal, this manifest reaches Git and Vercel. Remote prebuild rejects a missing/pending manifest, a missing/altered bound artifact or any mismatched ledger, including selectively committed outputs without their matching manifest. Every candidate link in the performance report must belong to the inventory. Recovery requires the original private journal; a partial deployment copy cannot reconstruct it. Commit the complete recovered output set, never manually reseal a mismatch or upload the private journal. The initial manifest binds the existing unchanged ledgers and public artifacts; it does not run evaluation or create outcomes. This protects accidental interrupted/partial releases, not deliberate replacement of all source and evidence by an administrator.

Use `npm run consensus:rollback -- --instrument SPY --horizon daily --to <archived-model-id-or-none> --reason '<public audit reason>'` to change future activation. An archived replacement must match the cohort/current engine and pass its original promotion/reservation/ancestry checks. `none` deactivates a cohort, including an incompatible incumbent. The command journals the registry/report update and an immutable public action record. It leaves previous snapshots, outcomes, models and consumed test windows unchanged. Reasons are public; never put private information or credentials in them. Synthetic tests exercise both restoring a qualified model and deactivation; no real model has been activated or rolled back.

Calendar coverage is still independently reviewed only for2026. Unsupported dates are never inferred from a price provider. The evaluator validates every in-range date against the complete official schedule, records unresolved instrument/horizon targets in `performance.pending`, and can score covered targets while a year-crossing horizon remains pending. Malformed or inconsistent in-range calendars still fail. A separately reviewed future schedule is needed before those later outcomes can resolve. The current Nasdaq source publishes2026; no2027 Nasdaq review is claimed.

A qualified model's probability does not override the rules' missing-evidence abstention.
