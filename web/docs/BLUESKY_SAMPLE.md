The free [Jetstream v2 live tail](https://bsky.network/docs/jetstream/) is a separate community source. It is not X, Instagram, all Bluesky or representative retail positioning. The [developer guidelines](https://bsky.network/docs/developer-guidelines/) require deletion/report handling and an accessible monitored contact. The owner explicitly selected **support@thedailyconsensus.com**. No email was sent and inbox delivery/monitoring has not been tested by Codex.

## Collection and interpretation

`npm run consensus:bluesky-private -- --seconds 600` captures a bounded live window (10–900seconds,100,000events/50MB maximum) using no API key. It processes creates/edits/deletes and account removals, handles duplicate/out-of-order record events, and keeps at most the latest qualifying post per account for each instrument. It does not retain post text, handles or raw account IDs. Matching record/account hashes exist only in memory during capture; sourceDigest is a hash of received frames, not a recoverable raw corpus.

The morning publisher can instead use `npm run consensus:bluesky-private -- --recent-seconds 840`. This starts at a timestamp cursor for a 14-minute provider window ending 15 seconds before collection begins. It requires the first event near the requested start and a subsequent event at or beyond the cutoff. A connection error, timeout, byte cap or event cap with an incomplete window saves no candidate. The recent cursor is the documented short Jetstream lookback and requires no key. The separate Bluesky HTTP archive replay requires authentication. Account removals and edits within the collected window still apply.

Eligible content is English-tagged original posts; replies, quotations, self-labelled content, old timestamps and missing-language posts are excluded. Instruments match explicit ETF/index cashtags or index names:SPY/SPX/S&P500,QQQ/NDX/Nasdaq100,IWM/RUT/Russell2000,DIA/DJI/DowJones,TLT. The aggregate market view additionally includes selected company cashtags AAPL/MSFT/NVDA/AMZN/GOOGL/META/TSLA, #stockmarket and the phrases stock market,US stocks,US equities,Wall Street (excluding Wall Street Journal),Federal Reserve,Treasury yields. This is a declared filter sample, not an index-weighted or representative population; large-cap and English-language selection biases remain.

The versioned local stance classifier groups upward, downward, mixed and unclassified language. It ties explicit outlooks and forward verbs to a single named market or ETF in each clause. Questions, negation, conditional phrasing, reported comments, hindsight and quotations remain unclassified. The market view can report mixed stances when one post has separate opposing ETF outlooks. Macro and company terms can qualify a market discussion without contributing a stance. Each instrument has its own counts and multi-instrument posts overlap. The classifier runs in memory without a model download or external text processor. Context, sarcasm and coordination can still mislead it. It has synthetic regression coverage and awaits independently labelled, rights-cleared real examples before any accuracy or forecasting claim.

The private candidate is `.consensus/bluesky-private/candidate.json` (0700directory/0600file). It contains only aggregate counts, window,filter diagnostics and source hash. A scan with fewer than10distinct matching accounts cannot be staged publicly. Instrument-specific distributions are also suppressed below10accounts. Provider/schema failure never creates a fabricated neutral reading.

## Private interpretation benchmark

X uses the `x-explicit-stances-v2` rules in the weekday digest and in the private interpretation benchmark. It accepts ticker headings, explicit bias labels, concise first-person calls and unambiguous forward price language. The Bluesky and Instagram rules retain their existing behavior. A reported distribution is still an interpretation of expressed language. Predictive validation requires separately approved outcomes and sufficient as-issued observations.

For a one-time private X research sample, run `node --experimental-strip-types scripts/research-x-posts.ts` with the local X public-search credential and sufficient API credits. The command targets 10,000 unique original posts in the recent-search window, reads up to 11,000 results, and keeps keyword-selected samples identifiable in the aggregate. `--supplement-replies` can add a distinct reply sample after a partial run in the same window, up to another 3,000 results. At the posted rate the two read caps total up to $70 before deduplication. Verify available credits before each run. The command is separate from weekday publishing. [X recent search](https://docs.x.com/x-api/posts/search-recent-posts) · [X pricing](https://docs.x.com/x-api/getting-started/pricing)

The SQLite file is created under the owner-only `~/.local/share/daily-consensus/` directory. Its `run` rows record unique eligible posts and its `cohorts` rows contain UTC dates, ETF, sample group, post counts and stance totals by author-day. A post can contribute to more than one ETF. Fewer than ten authors in a cohort suppresses its stance counts. Text, post IDs, account IDs and links are processed in memory and omitted from the database. Keyword samples are useful for exercising language rules and are unsuitable for estimating how common a stance is across X. Keep the database private. [X Developer Policy](https://docs.x.com/developer-terms/policy)

Use `npm run consensus:validate-social-private -- "$HOME/.local/share/daily-consensus/social-benchmark.json"` from `web` with an approved temporary corpus. The directory must be mode 0700, outside Git, and the regular file must be mode 0600. The JSON object has `schemaVersion: 1`, `collectedAt` and `expiresAt` in UTC ISO format with milliseconds, and `items`. Each item has `platform` (`x`, `instagram` or `bluesky`), `instrument` (MARKET or one of the five ETF symbols), `expected` (`upward`, `downward`, `mixed` or `unclassified`) and `text`. The command accepts a maximum 24-hour lifetime and writes no files. Remove the source file by expiry or sooner when required by the provider. Keep the output private.

Before sampling, confirm that the provider allows the collection, independent annotation and temporary local processing. Draw a fixed pre-forecast window and deduplicate authors per instrument during collection. Give independent annotators the same subject and ask them to mark the expressed outlook before seeing the classifier result or market outcome. Resolve label disagreements before running the benchmark. Include examples of questions, unrelated cashtags or hashtags, reported speech and conditional statements. Keep handles, post IDs, links and account keys out of the file. The command can detect duplicate text within a platform and instrument. Account deduplication and sampling eligibility must be verified upstream.

The versioned output reports expected-by-predicted counts, directional call rate and directional precision by platform and instrument. Groups with fewer than ten examples are suppressed. This checks interpretation. A separate prospective experiment must test whether a permitted aggregate adds predictive value with independently timestamped features and approved ETF outcomes.

## Publication and expiry

After checking a real qualifying candidate, `npm run consensus:bluesky-private -- --publish` stages an allowlisted aggregate into `lib/community-current.json`. It does **not** commit, deploy, create a consensus edition or report successful publication. Complete the existing clean Git/test/build/review/deploy/HTTPS/browser procedure before claiming it is public. Only aggregate counts/window/diagnostic event total and hash enter Git; raw content, exclusion hashes and private provenance files do not.

The Bluesky panel stays hidden until a valid aggregate has been staged for the build; an empty adapter does not add another blank card. The shared Community & retail disclosure can still contain the independently loaded Myfxbook view. `/api/community` serves a current, validated aggregate with no caching and excludes all raw/private fields. It withholds expired/future/invalid data. The client refreshes once a minute while open, fails closed on errors and never loads current data for a selected historical edition. Samples expire24hours after capture; source-version history may retain anonymous totals. No raw social corpus is archived, and these display counts do not enter consensus votes, coverage, immutable consensus editions, forecasts or model training. A successful transport or visualization does not complete the full social requirement.

## Reports, removals and opt-outs

The owner is responsible for monitoring support@thedailyconsensus.com and keeping the original report and response in that mailbox. This tool does not read the mailbox or send replies. Never infer monitored delivery merely from configuring a mailto link. Do not publish report content or complainant contact details.

For a verified request affecting a displayed sample:

1. Stage withdrawal with `npm run consensus:bluesky-private -- --invalidate`; this removes the private current candidate and writes a null public aggregate. Complete the authorized clean commit/deployment and verify `/api/community` returns unavailable. Clients remove their displayed aggregate on the next refresh (at most one minute after a successful deployment/check). Record exact response/deployment evidence privately. Old source/deployment versions may retain non-identifying aggregate totals until their display expiry; there is no retained individual content to retrieve or delete.
2. If an account/post requests future exclusion, provide a verified DID or AT post URI via stdin to `npm run consensus:bluesky-private -- --exclude-stdin`, keeping it out of shell arguments/history. This invalidates the whole current sample and stores only its one-way identifier hash in the private exclusion file. These hashes are pseudonymous, not anonymous, and are retained solely to honor opt-outs. The owner may remove an exclusion after an authenticated reversal request; preserve the request/response privately.
3. Collection, staging and withdrawal share the existing kernel publication lock. A busy lock means wait for the identified collector to finish, then repeat the requested operation; never steal/delete the lock or report a staged change as live. A concurrent collection cannot silently resurrect a withdrawal.
4. The owner responds to the report in the mailbox. Do not send outreach/replies automatically without explicit authorization.

Because all individual contributions are discarded at the end of capture, post-window edits/deletes cannot be mapped back into counts. The remedy is withdrawal of the whole current aggregate plus an optional future exclusion. This limitation is disclosed in the UI. It is not permission to create a training corpus.
